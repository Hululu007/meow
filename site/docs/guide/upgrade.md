# 升级与迁移

升级本身不复杂，出问题几乎都出在两件事上：**没备份**，以及**换了源包却没替换本地 jar 地址**。

## 升级前先做三件事

1. **记下当前版本**：设置页底部，或 [Releases](https://github.com/upchr/meow/releases) 里的 tag
2. **备份数据目录**：见 [备份与恢复](/guide/backup)
3. **确认源包还在手边**：升级不删配置，但从「内置源」形态迁移时必须重新导入

::: warning 跨大版本前一定先备份
1.0.x → 1.1.x 涉及运行时模块、配置字段的增减。出问题时能回退到旧数据和旧版本，
比事后排查快得多。
:::

## 各端升级

### Web / Docker

```bash
cd deploy/docker
docker compose pull
docker compose up -d
```

- 镜像 tag 由 `MEOW_VERSION` 决定，想固定版本就改 `.env`
- `data/` 是挂载目录，升级不覆盖
- 升级后 `docker compose ps` 四个容器都应是 `Up`，接口 503 说明 apiserver 没起来

### PC

- **应用本体**：设置 →「应用更新」→ 检查并安装
- **插件**：插件列表里远端版本更高时显示「可升级」，逐个点
- 应用与插件版本独立演进，**不要因为版本号不一致就以为装坏了**

::: tip 静默安装前先退出应用
如果手动跑 NSIS 安装包，先 `Stop-Process` 掉正在运行的猫窝，
否则文件占用会导致安装失败或装完还是旧版。
:::

### TV

1. 下载新 `meow-TV-<版本>.apk`
2. 覆盖安装（必须同签名，release 签名不变）
3. 运行时模块在设置 →「运行时模块」里单独更新

```bash
adb install -r meow-TV-<版本>.apk
```

覆盖安装**保留**应用数据；`adb uninstall` 会清空，需要重新导入配置。

### 飞牛 fnOS

两条路，效果一样：

- 应用中心 → 猫窝 → 升级
- 应用内 设置 →「应用更新」

应用内更新会自动重启服务，页面短暂断开后回到新版本；数据目录不动。

::: warning fnOS 不支持降级
应用中心不允许安装低于已装版本的包，回退要先卸载（会清数据，先备份）。
:::

## 从「内置源」的旧安装迁移

如果你之前用的是自带站点配置与 spider jar 的完整版，换成公开壳（或换新源包）时，
这一步最容易踩：

### 症状

导入成功、站点列表也有，但每个站点都报 `ClassNotFoundException` / `NoClassDefFoundError`，
或者干脆全是红的。

### 原因

导入时只换了站点表，**本地还留着旧配置里的 `spider` 字段**——指向一个已经不存在的 jar。
客户端按旧地址加载，自然找不到类。

### 正确做法

导入配置时勾选：

```
配置源 → 导入 → ☑ 用这份配置的顶层 spider 覆盖本地
```

界面上的原话是「用这份配置的顶层 spider 覆盖本地」，旁边的提示写着
「从全量版迁移/装源包时勾选；平时不要勾，会冲掉你手改的 jar 地址」。

### 迁移后核对四步

1. **站点数**与「带 ext」数量是否和源包声称的一致
2. 搜索一个常见片名，能出结果
3. 点进详情，有线路与集数
4. 播一集，`readyState` 到 4、时间在走

哪一步断了，见 [常见问题](/guide/faq) 与 [诊断手册](/reference/diagnostics)。

### 源包现在是 dex 主入口

迁移到新源包时，统一用 `config.all.json` + **dex** jar：Fongmi/TV 直接加载，
猫窝 JVM 用导入期 `Dex2Jvm` 自动转 class。`spiderJvm` 只是可选的 JVM 优化，
不再是必需产物。细节见 [导入源包](/guide/source-pack#一份配置通吃三端)。

## 跨版本变化速查

| 变化 | 起始版本 | 影响 |
|---|---|---|
| TV 运行时模块（Node / 弹幕） | 1.1.0 | 模块 `min_sdk` 26；旧壳不认模块条目 |
| 飞牛版内置弹幕插件 | 1.1.0 | 复用应用中心 Node 22 |
| fnOS 应用内更新 | 1.1.3 | 旧版只能走应用中心 |
| 配置支持 `spiderJvm` | 1.1.6 | 旧版不认该字段，仍需 `config.jvm.json` |
| JVM 导入期 dex→class（dex2jvm） | 1.1.7 | 源包只需 dex；旧 JVM 仍要 `config.jvm.json` 的 class jar |

更早的能力（端内网关、扫码推送）没有逐版本记录，判断依据以实际界面为准。
完整对照见 [版本兼容矩阵](/reference/compatibility)。

## 降级

| 端 | 做法 | 注意 |
|---|---|---|
| Docker | `.env` 改 `MEOW_VERSION` 后 `up -d` | 镜像 tag 必须存在 |
| PC | 卸载后装旧安装包 | 卸载默认保留 `%APPDATA%\com.meow.player` |
| TV | `adb install -d <旧 apk>` | `-d` 允许降级；签名必须一致 |
| fnOS | 先卸载再装旧 fpk | 卸载清数据，先备份 |

降级到不认 dex2jvm 的旧 JVM 时，`config.all.json` 里的 dex 不会被转换：
改用 `config.jvm.json`（顶层 `spider` 指向 class jar），或把 `spider` 指回 class jar。
`spiderJvm` 这类未知字段会被旧版忽略。

## 升级后自检

```
1. 后端健康：Web 看 /api/health，PC 看插件状态「运行中」
2. 站点数：与升级前一致（迁移除外）
3. 搜索 → 详情 → 播放 三段都通
4. 收藏与进度还在（确认数据目录没换）
```

第 4 步失败通常意味着数据目录被改了（容器挂载、便携版换了位置），见 [备份与恢复](/guide/backup)。

## 常见失败

| 症状 | 原因 | 处理 |
|---|---|---|
| 升级后站点全红 | 旧 `spider` 地址残留 | 重新导入并勾选覆盖 spider |
| 插件列表显示「需要更高版本的应用」 | 插件 `min_app_version` 高于当前应用 | 先升应用，或装旧插件 |
| 运行时模块装不上 | 壳版本低于 1.1.0，或 `min_sdk` 26 不满足 | 升壳 / 换支持 Android 8.0 的设备 |
| 升级后端口变了 | 插件端口协商顺延 | 设置页看实际端口，别写死 |
| fnOS 升级后版本没变 | 应用中心与内置更新源短暂不同步 | 隔几分钟重试，或回应用中心升 |
| 覆盖安装后配置没了 | 装成了「卸载再装」而不是覆盖 | 从备份恢复 |
