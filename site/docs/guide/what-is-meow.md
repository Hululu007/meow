# 这是什么

猫窝 Meow 是一个**跨端影视客户端宿主**。它本身不提供影片，也不附带站点配置；
它解决的是「同一份内容源，怎么在浏览器、Windows、Android（TV / 手机）和 iPhone / iPad 上都能跑」这件事。

## 一句话模型

四个出口，一套内核：

```
   Web     ──┐
   PC      ──┤
   Android ──┼──▶  同一个宿主（后端 / 端内）  ──▶  源包（站点清单 + 爬虫包）
   iOS     ──┘
```

传统做法是每个平台各写一套加载器，源包换一次要改好几处；这里把「加载源包 + 统一配置」
收成一层，四端复用，差异只剩外壳。实现细节见 [架构文档](/dev/architecture)。

## 端与形态

| 端 | 形态 | 后端 | 源包在哪加载 | 适合谁 |
|---|---|---|---|---|
| **Web** | Docker 四容器 | 容器里的 JVM 后端 | 后端 | NAS / 服务器用户，浏览器直接看 |
| **PC** | Tauri 2 桌面应用 | 随应用启动的本机后端 | 本机后端 | Windows 桌面 |
| **TV** | Android 应用 | 端内直接执行，也可连后端 | 电视本机（或后端） | 安卓手机 / 平板、电视盒子、投影仪；遥控器或触屏操作 |
| **iPhone / iPad** | IPA（未签名，自签侧载） | 端内 JVM（OpenJDK Zero） | 手机本机 | iPhone / iPad 用户；不装 App 也可用 Safari |
| **飞牛 fnOS** | fpk 套件（Web 版打包） | 应用中心托管的后端 | 后端 | 飞牛 NAS 用户，在应用中心安装与升级 |

Web / PC / TV / iOS 共用同一份前端，PC 与 TV、iOS 只是不同的壳：PC 负责进程管理与插件安装，
TV 负责遥控器导航与端内加载，iOS 用端内 JVM 直接跑同一个后端；
fnOS 是 Web 版的套件封装，不用自己维护 compose。
实现细节见 [架构文档](/dev/architecture)。

## 和 TVBox / Fongmi 类客户端的关系

猫窝能直接导入这些客户端在用的 CatVod 源包（站点清单 + 爬虫包），
换过来不用重新找源。区别在宿主这一层：

- **三端同一个后端**：浏览器、Windows 桌面、电视看到的是同一份站点表与同一份片库
- **数据能带走**：收藏与进度存在各端本机，也能经同一后端或 WebDAV 跨端同步
- **宿主自带周边**：片库与转码、直播、弹幕聚合、AI 助手在同一套里，不用再拼几个工具

只想要一个电视端播放器，现成客户端更轻；需要多端一致和这些周边能力时，猫窝更合适。

## 不是什么

::: danger 边界
- **不是内容站**：仓库没有影片、直播源、站点配置或爬虫包。
- **不是聚合搜索服务**：搜索范围完全取决于你导入了哪些源。
- **不是开源软件**：许可禁止商业使用，只允许个人学习、研究、自用与修改。
:::

源包从哪里来由你决定：私有 Release、NAS、对象存储、自建静态服务都可以。
项目只负责提供导入入口与加载能力，导入方法见 [导入源包](/guide/source-pack)。
