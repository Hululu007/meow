# 这是什么

猫窝 Meow 是一个**跨端影视客户端宿主**。它本身不提供影片，也不附带站点配置；
它解决的是「同一份内容源，怎么在浏览器、Windows 桌面和 Android TV 上都能跑」这件事。

## 一句话模型

```
                  ┌─────────────────────────────┐
   Web  ──────────▶                             │
   PC   ──────────▶   同一个 JVM 宿主           │──▶  spider jar（第三方分发）
   TV   ──────────▶   同一份 spider jar         │
                  │   同一套配置语义             │
                  └─────────────────────────────┘
```

内容源（spider）由第三方以 jar 形式发布。传统做法是每个平台各写一套加载器：
桌面用 `Class.forName`，Android 用 `DexClassLoader`，浏览器没 JVM 就得再实现一遍。
这个项目把宿主抽出来做一次，三端复用，差异收敛在「加载器」和「壳」两层。

## 三端形态

| 端 | 形态 | 后端 | 加载方式 | 适合谁 |
|---|---|---|---|---|
| **Web** | Docker 四容器 | 容器内 apiserver | JVM `classpath` | NAS / 服务器用户，浏览器直接看 |
| **PC** | Tauri 2 桌面应用 | 随应用启动的 sidecar | 同上 | Windows 桌面，需要离线缓存与投屏 |
| **TV** | Android WebView 壳 | 无，端内执行 | `DexClassLoader` | 电视盒子、投影仪（遥控器）；安卓手机 / 平板也能装（触屏） |

三端共用同一份 Vue 前端（`client/apps/web`），PC 与 TV 只是不同的外壳：
PC 壳负责进程管理与插件安装，TV 壳负责遥控器导航与端内网关。

还有第四种形态：**飞牛 fnOS 原生套件**（fpk）。它把 Web 版打成 NAS 应用，
在应用中心安装与升级，不需要自己维护 compose。

## 能力范围

| 模块 | 能力 |
|---|---|
| 浏览与搜索 | 首页推荐、分类分页、详情、聚合搜索（自适应预算 / 失效跳过 / 结果缓存）、搜索历史、收藏与追剧更新 |
| 播放 | HLS/DASH、`parse=1` 解析、手动/自动换线、续播、0.5–3x 倍速、片头尾与中插跳过、选集连播、字幕（SRT/ASS/HLS 内嵌）、画中画、DLNA 投屏、假死与 404 看门狗 |
| 弹幕 | 多源降级（顺序可配）、手动搜索、屏蔽/密度/透明度/字号/速度、本地缓存、canvas 60fps、片尾预取 |
| 直播 | 站点聚合 + IPTV m3u/txt、换台、坏台自动跳、左右切线路 |
| 片库与缓存 | WebDAV / 本地 / SMB 片库，Range 直连，按需转 HLS，海报刮削；单集/整季离线缓存、断点续传、离线优先 |
| 跨端状态 | 收藏/进度/历史/观看统计/偏好跨端通道；WebDAV 同步与备份（快照式，非实时） |
| 源与配置 | 多仓配置导入（探测 + 自动备份）、站点健康/停用/批量管理、安全 DNS/DoH、drpy JS 运行时 |
| 设置与 AI | 外观/网络/弹幕/播放/搜索/数据维护；AI 助手（规则 + 语义工具 + 模型层） |
| 三端形态 | Web 四容器；PC 插件化 + 内置 MCP + 在线更新；TV 端内网关 + `DexClassLoader` + 遥控导航 + 扫码配置 |

完整的功能取舍与不做的清单见 [已知限制](/reference/limits)。

## 不是什么

::: danger 边界
- **不是内容站**：仓库没有影片、直播源、站点配置或 spider jar。
- **不是聚合搜索服务**：搜索范围完全取决于你导入了哪些源。
- **不是开源软件**：许可禁止商业使用，只允许个人学习、研究、自用与修改。
:::

源包从哪里来由你决定：私有 Release、NAS、对象存储、自建静态服务都可以。
项目只负责提供导入入口与加载能力，导入方法见 [导入源包](/guide/source-pack)。
