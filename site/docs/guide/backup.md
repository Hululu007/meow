# 备份与恢复

收藏、观看进度、站点配置都在本地数据目录里。**这些丢了不会同步回来**，因为项目没有账号体系，也不上传任何用户数据。

## 三端数据在哪

| 端 | 位置 | 怎么找 |
|---|---|---|
| **Web / Docker** | 仓库 `data/`（容器内 `/data`） | `deploy/docker/docker-compose.yml` 的挂载 |
| **PC** | `%APPDATA%\com.meow.player` | 文件资源管理器地址栏粘贴即可 |
| **TV** | 应用私有目录 | 需要 root 或 `adb backup`；普通用户建议用 WebDAV 同步代替 |
| **飞牛 fnOS** | 应用的 `var/data` | 应用中心的应用数据区，升级不覆盖 |

::: tip 先确认后端用的是哪个目录
PC 上如果连的是**远端后端**（设置页手填了地址），数据在远端机器上，
本机 `%APPDATA%` 里只有界面偏好。备份前先看清楚连的是谁。
:::

## 哪些必须备份

| 内容 | 文件 | 丢了会怎样 |
|---|---|---|
| **站点配置** | `config.sites.json` | 要重新导入源包；旧 jar 地址可能已失效 |
| **运行时策略** | `policy.json` | 弹幕服务地址、解析偏好、DNS 设置丢失 |
| **收藏 / 进度** | `state-favorites.json`、`state-progress.json` | **不可恢复**，跨端同步也救不回来 |
| **站点健康** | `site-health.json` | 可重新探测，不用备份 |
| **封面与转码缓存** | `posters/`、`cache/` | 可重建，体积大，建议排除 |
| **弹幕服务数据** | `danmu/` | 弹幕缓存，可重建 |
| **插件目录** | PC `plugins/`、Web 容器内 | 可重新下载，不用备份 |

**只备份 `data/` 就够了**，它是所有不可再生成状态的唯一来源。
体积敏感的话，排除 `cache/`、`posters/`、`danmu/` 三个子目录，剩下的通常只有几 MB。

## 怎么备份

### Web / Docker

```bash
cd deploy/docker

# 1. 停服务，保证数据库文件一致
docker compose stop

# 2. 打包（data 在仓库根目录）
tar -czf meow-data-$(date +%Y%m%d).tar.gz -C ../.. data

# 3. 起回来
docker compose up -d
```

::: warning 不要热备份 SQLite
服务运行时直接复制 `data/` 可能拿到写了一半的数据库。
停 5 秒比恢复一个坏库划算。
:::

### PC

1. 完全退出猫窝（托盘也退）
2. 复制 `%APPDATA%\com.meow.player\data` 到备份位置
3. `plugins/` 可以不备份——重装后重新下载即可

### 飞牛 fnOS

应用中心 → 猫窝 → 停止 → 复制应用数据目录 → 启动。
系统级备份（快照/整机备份）也能覆盖，但要注意应用数据区是否在备份范围内。

### TV

普通设备拿不到应用私有目录。可行的替代：

- **WebDAV 同步**：把收藏/进度同步到自己的 WebDAV（见下文）
- **扫码推送配置**：把配置地址推给电视，重装后一步恢复
- root / 开发设备可以用 `adb backup`，但恢复时同样受签名限制

## 怎么恢复

```
1. 装**同版本**或更高版本的应用
2. 停掉服务（容器 stop / 应用退出 / fnOS 停止）
3. 用备份覆盖 data 目录
4. 启动，检查站点数、收藏、进度
```

::: danger 不要跨大版本直接覆盖
低版本的数据目录可能缺少新版本需要的字段。先升级应用再恢复，
或者恢复后让应用自己迁移。跨大版本恢复前再留一份原备份。
:::

## 换机器迁移

1. 新机器装**同版本**应用
2. **先启动一次再停掉**——让新目录结构生成出来
3. 用旧机器的 `data/` 覆盖过去
4. 启动后核对：站点数、收藏、进度
5. PC 上如果端口变了（9979→9980…），设置页确认后端地址，别用写死的端口

TV 换机没有好办法，用扫码推送配置 + WebDAV 同步最快。

## WebDAV 同步不是备份

设置里的 WebDAV 是**快照式同步**，不是增量备份：

- 它按快照覆盖，多端同时改会互相覆盖
- 它只同步状态（收藏/进度/偏好），不同步片库文件与离线缓存
- 同步失败不会阻塞播放，但也**不会给你报错**

所以：**重要数据额外留一份本地备份**，别把 WebDAV 当唯一保障。

## 什么时候必须备份

| 时机 | 原因 |
|---|---|
| 升级前 | 跨版本字段变化，回退需要旧数据 |
| 换源包前 | 旧配置会被覆盖（覆盖导入有一次性撤销，但只保一次） |
| 换机器 / 重装系统 | 没有云同步 |
| 迁移存储卷（如 NAS 换盘） | 路径变化后应用可能找不到数据 |
