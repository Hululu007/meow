# 插件与安装

PC 版安装包只有壳（约 6 MB）。后端、drpy、弹幕、Node 运行时全部是插件，
第一次打开必须从插件源拉下来。这样「只用播放」的用户不用下 100 MB。

## 为什么要插件化

| 方案 | 安装包 | 代价 |
|---|---|---|
| 后端打进安装包 | 40 MB+ | 所有人都要为用不到的功能付体积 |
| 全部插件化 | 约 6 MB | 首次使用多一步下载 |

代价是首次体验：装完打开是「后端未连接」。这不是错误，是设计。

## 插件生态里有什么

| 插件 id | 能力 | 作用 | 必需 |
|---|---|---|---|
| `apiserver` | `backend` | 宿主后端：搜索 / 详情 / 播放 / 代理 | 是 |
| `danmu-api` | `danmaku` | 弹幕多源聚合 | 否 |
| `drpy` | `runtime` | Node 运行时，跑 `.js` / drpy 源 | 强烈建议 |
| `node` | `tool` | Node 可执行文件，`danmu-api` 的依赖 | 跟随依赖 |

`apiserver` 与 `danmu-api` 的 id 是**应用内置识别**的：前端靠 `capability: "backend"`
认后端，靠 `capability: "danmaku"` 认弹幕服务。其他 id 也能装、也能被启停，
但应用不知道它们的用途，不会自动接线。

::: warning 官方清单当前是空的（已知问题）
官方清单把插件条目都标记成了隐藏，应用里「可安装」列表可能为空。当前可在
[Releases](https://github.com/upchr/meow/releases) 手动下载 `apiserver-<版本>.zip`，
用「导入本地包」安装；`drpy`、`danmu-api`、`node` 条目待补，可先自建源
（见 [自建插件源](/ecosystem/plugin-source)）。
:::

## 安装流程

```
读插件源 → 拿 packages.json → 选插件 → 下载 zip
   → 校验 SHA256 → 解压到 plugins.d/ → 原子 rename 到 plugins/
   → 启动进程（Job Object 随主进程清理）→ 健康检查
```

几个关键设计：

- **SHA256 不匹配就删除并报错**，不会留下半个插件
- **解压与替换都是原子 rename**：同盘 rename 不会中断出半截目录
- **端口自动协商**：首选端口被占用就顺延（`apiserver` 是 9979→9985）
- **健康检查通过才算装好**：默认 45 秒超时，每 400–800 ms 轮询
- **失败自动回滚**：旧目录先改名为 `.bak`，新版起不来就改回来并重启旧版

## 目录布局

```
%APPDATA%/com.meow.player/
├── plugins/
│   ├── apiserver/
│   ├── danmu-api/
│   └── node/
├── plugins.d/
│   └── apiserver.bak/        升级失败时的旧版本
├── data/
│   ├── policy.json           运行时策略（含自动接线的地址）
│   └── ...                   观看记录等
└── enabled.json              启用状态
```

`data/` 与插件目录分离：卸载或升级插件不会动观看记录与配置。

## 自动接线

带 `capability` 的插件启动后，应用会把它的实际地址写进 `policy.json`：

```json
{
  "danmakuApi": "http://127.0.0.1:9321",
  "jsRuntime": "http://127.0.0.1:9330"
}
```

规则：**不覆盖用户手填的值**。如果你之前把 `danmakuApi` 指到 NAS 上的服务，
插件启动不会把它改回本机。想交还给插件管理，清空该字段即可。

## 版本规则

应用、后端插件、弹幕插件、Node 运行时**各自独立演进**：

- 应用与 `apiserver` 通常同版发布；`danmu-api`、`node` 跟随各自上游，
  与应用版本**无关**。当前实际版本以更新清单与插件列表显示为准
- 版本比较用语义化版本，远端更高才显示「可升级」
- `min_app_version` 不满足时拒绝安装并提示需要更高版本的应用

不要为了「看起来整齐」强行对齐版本——每次改前端都重发 37 MB 的后端包没有意义。

## 从哪拿插件

| 来源 | 说明 |
|---|---|
| 项目 Release 的 `packages.json` | 官方清单；**更新源留空时用的就是它**（内置默认），自建源才手填地址 |
| 自建静态服务 | 见 [自建插件源](/ecosystem/plugin-source) |
| 别人的源 | 只要清单格式与 SHA256 正确就能用 |

::: warning 第三方插件源有风险
插件是**本地可执行程序**，安装即在你机器上运行。只使用你信任的源，
并确认清单里的 `sha256` 与下载内容一致。应用本身只做校验，不判断插件行为。
:::
