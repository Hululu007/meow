# 已知限制

这些不是待办清单，而是**设计边界或当前无法解决的问题**。遇到时先看这里，
能省掉一轮排查。

## 源与播放

### 源站时效

不少源的播放地址**绑定客户端 IP 且几分钟过期**。表现：

- 刚点开能播，过几分钟断流
- 同一地址在手机上能播、在电视上不能
- 换线路后恢复，但过一阵又断

这是上游的防盗链策略，客户端无法绕过。重新进详情页取新地址是最快的恢复方式。

### 线路存活

上游源经常整条失效。客户端能做的是：一条线路失败时把同台/同源的其他线路试完，
再换源。**它不能凭空造出可用线路。**

### `type: 0` 解析源在 Web / PC 不可用

`parses[].type = 0` 表示用 Android WebView 嗅探播放地址。Web 与 PC 后端没有 WebView，
这类解析器不可用。TV 端因为本身有 WebView，能跑。

这是架构限制，不是配置问题。

### 多画质没有常驻选择器

只在播放失败页给「换个画质」出口，不做常驻清晰度菜单。
原因是多数源只提供一条流，做了也是空菜单。

### 浏览器端全屏限制

浏览器要求全屏必须由用户手势触发。换集时全屏元素离开 DOM 会被强制退出，
之后只能进伪全屏。桌面端已在应用层处理，浏览器端属平台限制。

### 缓存与源站脱节

已缓存的媒体文件可以离线看，但重新拉取清单需要源站可达。
表现为「旧集能看，新集拉不到」。

## 弹幕

### 不是所有片都有弹幕

内置直连只覆盖几个主流平台。冷门片、老片、非大陆内容经常是空的。

### 聚合服务的首屏延迟

自建 `danmu_api` 首次抓取一集通常要 7–10 秒，内置直连只要 1–3 秒。
默认顺序是内置直连优先，聚合服务在后台补缓存。

### 手动选择的来源不会落盘

手动搜索选中的弹幕源只对当前播放生效，不会写进缓存策略。

## TV 专项

### 投影仪（armeabi-v7a）聚合搜索可能崩溃

32 位 ART 在并发分配下存在已知的 GC 崩溃（`ConcurrentCopying::MarkNonMoving` SIGABRT）。
触发条件是聚合搜索的并发度与分配速率。目前的做法是限制并发、降低预热强度，
但**没有根治**。

表现为搜索时进程直接消失，没有错误页。低端 32 位设备建议减少启用站点数。

### 纯本机形态下个别遥控器进不了地址输入框

部分遥控器无法把焦点移到「配置地址」输入框。绕过方式：

- 用手机扫码推送配置
- 先切到后端模式，在手机/电脑上完成配置

### 端内网关不对外

网关只在应用进程内监听，退出应用即停止。它不是给局域网其他设备用的服务。

## 生态与平台

### PC 应用与插件版本独立

前端改了不必重发 37 MB 的后端包。副作用是「应用 1.1.6 + 后端 1.1.5」这种组合是正常的，
不要按版本号是否一致判断装没装好。

### 公开 Release 不含源包

仓库与 Release 都不分发 spider jar 与站点配置。原因见 [许可与免责](/reference/license)。

### 私有 Release 的资产客户端下不了

插件下载器默认不带 `Authorization`。私有仓的 Release 资产对客户端是 401/404。
源包请放在：

- 公开只读的对象存储
- 局域网静态服务
- 或客户端能带 token 的自建服务

### 商业使用禁止

见 [许可与免责](/reference/license)。这不是可以商量的限制。

## 明确不做的事

| 不做 | 原因 |
|---|---|
| 内置任何源或片源 | 合规与版权 |
| 内置代理 / 翻墙 | 与客户端职责无关 |
| 账号体系与云端同步 | 端内状态 + WebDAV 已够用，避免收集用户数据 |
| 广告与推荐算法 | 不做内容分发 |
| 移动端原生 App | Web 已覆盖，维护成本不划算 |
| 应用市场上架 | 分发渠道与合规成本 |
