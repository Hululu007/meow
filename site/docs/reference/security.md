# 安全与隐私

这一页说明三件事：**你装的是什么**、**它会把什么发出去**、**哪些配置会把风险放大**。

## 数据收集：没有

- 没有账号体系，不需要注册登录
- 没有遥测、埋点、崩溃上报（代码里没有任何第三方统计 SDK）
- 不上传播放记录、收藏、搜索词
- 唯一的远程请求是你自己导入的源站、你配的弹幕服务、你配的模型

::: tip 怎么验证
用抓包工具（Charles / mitmproxy）看客户端发出的请求，域名应该只有：
你导入的源站、`proxy` 字段里的 host、你填的弹幕服务与模型地址。
:::

## 本地存了什么

| 数据 | 位置 | 说明 |
|---|---|---|
| 站点配置 | `data/config.sites.json` | 含源站地址与 jar 地址 |
| 用户状态 | `data/state-*.json` | 收藏、进度、历史 |
| 运行时策略 | `data/policy.json` | 弹幕地址、DNS、令牌 |
| 缓存 | `data/cache/`、`posters/` | 转码分片、封面 |

没有任何一项加密。共用电脑的话，这些文件谁都能读——这是本地应用的常态，
但值得知道。

## 哪些配置会放大风险

### 1. 把后端暴露到局域网 / 公网

`apiserver` 默认只绑 `127.0.0.1`。改成 `0.0.0.0` 之后：

- 同一网段任何人都能调 `/api/*`：删收藏、改配置、拿播放地址
- 如果没设 `MEOW_AUTH_TOKEN`，**没有鉴权**
- 公网暴露等于把这些接口交给扫描器

必须暴露时的最低要求：

```
1. 设置 MEOW_AUTH_TOKEN（长随机串）
2. 只在可信网络或 VPN 内
3. 前面挂反向代理 + HTTPS
4. 不要直接把 30011 映射到公网
```

### 2. 插件源

插件是**本机可执行程序**。安装即运行，权限和你一样。

- 只使用你信任的源
- 确认清单里的 `sha256` 与下载内容一致
- 应用只做校验，不判断插件行为

### 3. 源包与 spider jar

spider jar 是第三方代码，在宿主 JVM（Web/PC）或 TV 进程里**直接执行**，
能力等同于本机程序：能读文件、发网络请求。

- 来源不明的 jar 等于来源不明的可执行文件
- TV 端的 `DexClassLoader` 同理

这不是这个项目特有的问题，是这类「插件化影视客户端」的共同前提。

### 4. 跨域设置

`MEOW_CORS=*` 是为了方便局域网调试。改成白名单后，注意写门禁与下发白名单
用的是同一份判据（旧版本曾出现两份手抄白名单漂移，导致首页第一个请求 403）。

## 密码与令牌存在哪

| 项 | 存哪 | 备注 |
|---|---|---|
| `MEOW_AUTH_TOKEN` | `.env` / 容器环境 | 明文，别提交进 git |
| 模型 `apiKey` | 浏览器 localStorage / 本机偏好 | 明文，共用电脑注意 |
| WebDAV 凭据 | 后端数据目录 | 明文 |
| 源站 cookie | 源包配置或 `policy.json` | 由源决定 |

项目没有密钥管理系统，也不打算有。**敏感信息就是明文存在本机**，
自己决定要不要放进共享设备。

## 恶意源能做什么

| 能力 | 说明 |
|---|---|
| 读本机文件 | jar 里可以 `new File(...)` |
| 发任意网络请求 | 包括内网地址（SSRF） |
| 读取播放器上下文 | 同进程内可见的数据 |

所以「随便找个源包导入」和「随便运行一个 exe」风险等级相同。

## 建议

- 源包、插件只从自己信任的渠道获取
- 不把后端裸奔到公网；要远程看，用 VPN
- 定期备份 `data/`（见 [备份与恢复](/guide/backup)）
- 共用电脑时不要保存模型 key 与 WebDAV 凭据
