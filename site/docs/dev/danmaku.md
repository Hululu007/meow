# 弹幕

弹幕是**多源竞争**的：同一集同时向几个来源要数据，谁先回谁用，全失败才降级。
这一页说明优先级、降级、缓存与播放器侧的调度。

## 一、四个来源

| 来源 key | 是什么 | 特点 |
|---|---|---|
| `iqiyi` | 爱奇艺直连 | 最快（1–3 s），覆盖面中等 |
| `tencent` | 腾讯直连 | 快，彩色弹幕保留原色 |
| `danmu_api` | 自建聚合服务（插件或容器） | 慢（7–10 s），但覆盖面最广 |
| `aggregator` | 肥猫联盟等公共聚合 | **兜底**，大面积失效，仅作最后一条 |

后端优先级写死在 `server/host/src/shared/ApiServer.java`：

```java
private static final String[] DANMAKU_PRIORITY = {"iqiyi", "tencent", "danmu_api", "aggregator"};
```

这个数组决定两件事：**排序**（结果里谁排前面）和**降级顺序**（前面的全失败才看后面的）。

## 二、前端可覆盖顺序

`policy.json` 的 `danmakuOrder` 数组可以改实际尝试顺序：

| 配置 | 效果 |
|---|---|
| 不写 | 用后端默认：`iqiyi → tencent → danmu_api → aggregator` |
| `["aggregator"]` | 只用自建聚合，首屏预算从 6 s 放宽到 10 s |
| `["iqiyi","tencent","aggregator"]` | 跳过自建服务（未装插件时的常见配置） |

设置页的「内置直连优先 / 弹幕 API 优先」两个选项，底层写的就是这个数组。

::: warning 不是严格串行
后端对同一集的多个来源是**分片并行**抓取，不是挨个试。优先级影响的是
结果排序与最终的降级判断，不是请求发起顺序。所以「最先出现的」不一定是最高优先级的。
:::

## 三、降级与空结果

```
并发发起（按优先级排序的来源集合）
   ├─ 任一来源命中 → 返回，按优先级排序
   ├─ 全部失败     → 返回空数组（不是错误）
   └─ 单源超时     → 跳过该源，不影响其他
```

「没有弹幕」和「请求失败」在接口层是同一个结果：空数组。所以前端不能靠
「有没有报错」判断，只能看条数。

常见空结果原因，按命中率：

1. 这一集确实没有（冷门片、老片）
2. 自建服务没起，而 `danmakuOrder` 只写了 `danmu_api`
3. 片名与平台命名差异太大，搜索匹配不上
4. 源站风控（要求特定 UA / 地域）

## 四、缓存

| 层 | 位置 | 生命周期 |
|---|---|---|
| 后端内存 | 进程内，按 `site/episode` 键 | 重启清空 |
| 前端 IndexedDB | 浏览器本地 | 30 天，有容量上限 |
| 磁盘（离线缓存时） | `data/danmu/` | 跟随离线缓存条目 |

前端命中缓存时**不再请求后端**，所以「同一集永远拿不到升级后的数据」——
这是缓存优先的固有代价。要强制刷新，清掉该集缓存重新进入。

缓存上限触发清理时，只清理最久没看的；**正在播放的那一集永远保留**。

## 五、播放器侧的调度

弹幕渲染在独立 canvas 上，和视频时间做插值同步。三条硬规则：

**1. 暂停跟视频走**

视频缓冲（`waiting`）时弹幕层一起暂停，恢复后继续，**不清屏**。
早期实现会在缓冲恢复时判定为 seek，导致整屏弹幕消失后从右边缘重打。

**2. 容差要大于插值超前**

同步检查的容差是 0.75 s，必须大于播放器插值的超前量（约 0.4 s），
否则缓冲恢复必然被判成「跳转」。

**3. 倍速影响弹幕速度**

1.25x 以上时弹幕滚动速度同比加快，密度按屏幕宽度动态收敛，避免高倍速下糊屏。

## 六、渲染参数

| 项 | 可调 | 存储位置 |
|---|---|---|
| 屏蔽词 | 关键词 / 正则 | `policy.json` |
| 密度 | 同屏上限 | 前端偏好 |
| 透明度 | 0–100% | 前端偏好 |
| 字号 | 小 / 中 / 大 | 前端偏好 |
| 速度 | 滚动速度 | 前端偏好 |
| 显示区域 | 全屏 / 上半 / 滚动 | 前端偏好 |

屏蔽词的分隔符与搜索噪音词表一致（逗号 / 中文逗号 / 分号 / 换行），
用户不用记两套写法。

## 七、改这块之前

| 要改什么 | 先看 |
|---|---|
| 加一个弹幕来源 | `DANMAKU_PRIORITY` + 后端抓取分支 + 前端 `danmakuOrder` 的合法值 |
| 调同步容差 | `VideoPlayer.vue` 的 `sync()`，容差必须 > 插值超前量 |
| 改缓存策略 | 前端 IndexedDB 封装；注意「正在播放的集不清理」这条 |
| 接自建服务 | [插件系统](./plugin-system.md) 的 `inject` 机制；服务地址写进 `policy.json` 的 `danmakuApi` |
