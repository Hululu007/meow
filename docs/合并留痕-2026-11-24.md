## 8. 下次并行合并的检查单

1. 一个会话一个分支 + 一个 worktree；开工就建，不共用主工作区。
2. main 只做集成；合并窗口内冻结 main，功能会话不 commit/push main。
3. 会话结束交状态卡：worktree、branch、HEAD、dirty 数、改了哪些文件、测试、ignored 证据。
4. 合并前先 `git merge-tree --write-tree main <branch>`；再用 `git cherry` / `patch-id`
   查重复提交（`bce2a9d` 这种）。
5. 工作区版本与 main 比较时先做 3-way diff，判断“旧版本”还是“独有改动”；
   不要整文件拷，不要 `git add -A`。
6. 合并前 `git ls-files --eol` 检查 CRLF；需要时先归一化 LF。
7. 每合一步跑 `javac` + `vitest` + `vue-tsc`；动 build.gradle 再打 TV APK。
8. 清理前先归档 `tmp/` 证据；删 worktree 前确认没有未提交内容。
9. 合并后的分支用 tag 留底，再删分支/worktree；`.zcode/worktrees/*` 不动。
10. push main、打 tag、跑 CI 都要单独确认。
